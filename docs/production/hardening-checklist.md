# Production hardening checklist

Use this before exposing Luma CMS to the public internet.

## Application

- [ ] `APP_ENV=production`
- [ ] `APP_DEBUG=false`
- [ ] Strong unique `APP_KEY` (generated by `luma:install` or `key:generate`)
- [ ] Change default admin password (`LUMA_SEED_ADMIN_PASSWORD` / `luma:install --admin-password`)
- [ ] `LOG_LEVEL=warning` or `error` in production

## HTTP / TLS

- [ ] Terminate TLS at reverse proxy (Caddy, Traefik, nginx, cloud LB)
- [ ] Redirect HTTP → HTTPS
- [ ] Enable HSTS at the edge (document policy for your domain)
- [ ] Set `APP_URL` to the public HTTPS origin

## Authentication

- [ ] Review Sanctum token lifetime for admin sessions
- [ ] Optional: force password change on first admin login (not in MVP)
- [ ] Restrict Luma Studio (`/admin/`) by network or additional auth at reverse proxy if needed

## Integrations

- [ ] Webhook URLs must be HTTPS (validated by API)
- [ ] Rotate integration tokens periodically; revoke unused tokens
- [ ] Monitor webhook delivery failures in Studio

## Public endpoints

- [ ] Form honeypot enabled (built-in)
- [ ] Rate limit on `POST /public/forms/{slug}/submit` (10 requests/minute per IP)
- [ ] Review published pages and public form exposure

## Docker

- [ ] Change default PostgreSQL password (`POSTGRES_PASSWORD`, `DB_PASSWORD`)
- [ ] Keep `luma-cms` code mount read-only in nginx where possible
- [ ] Persist only required volumes (`luma-api-storage`, `luma-postgres-data`)
- [ ] Run queue worker and scheduler containers (not sync driver)

## Operations

- [ ] Scheduled backups (see [backup-restore.md](backup-restore.md))
- [ ] Document upgrade: pull → `migrate --force` → restart `queue` / `scheduler`
- [ ] Monitor disk usage for `storage/app` (media growth)

## Deferred (not in MVP)

- Redis + Horizon for queues at scale
- S3 media driver
- WAF / ModSecurity rules
- Automated security scanning in CI
