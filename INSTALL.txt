Luma CMS — Install guide (shared hosting, no Composer required)
===============================================================

This guide is for a normal hosting user. You do NOT need Composer, npm, Docker,
terminal commands, or custom nginx/apache configuration.

Primary install path
--------------------

1. Upload and extract the release zip into your site folder (subdomain or domain
   document root), for example:

   ~/sites/example.com/stage/

2. In your hosting panel (BrainyCP, HestiaCP, cPanel, etc.), select PHP 8.3 or
   8.4 for this domain.

3. Point the domain document root at the folder where you extracted the archive.
   You do NOT need to change it to apps/api/public — root index.php handles that.

   The archive includes at the **top level** (same folder as apps/):
   - index.php
   - install.php       (shortcut → setup wizard)
   - luma-requirements.php
   - .htaccess         (may be hidden in file manager — enable "show hidden files")

   When extracting the zip, put files directly in your site folder.
   Do NOT leave them inside a nested staging-shared/ subfolder.

4. Open your site in a browser:

   https://your-domain.example/

   If CMS is not installed yet, you are redirected to the setup wizard at
   /admin/setup automatically.

   https://your-domain.example/install.php

   Optional first check:

   https://your-domain.example/luma-requirements.php

5. On first visit, Luma may copy apps/api/.env.shared.example to apps/api/.env
   if the folder is writable. Otherwise copy it manually in File Manager:

   apps/api/.env.shared.example  →  apps/api/.env

   Edit apps/api/.env if needed:
   - APP_URL = your site URL
   - DB_* credentials if you use MySQL before the wizard
   - Leave SESSION_DRIVER=file and CACHE_STORE=file until setup finishes

6. Make these directories writable by the web server user:

   apps/api/storage/
   apps/api/bootstrap/cache/

7. Complete the visual installer at /admin/setup, then sign in at /admin/login.

8. Complete onboarding, create your first page, publish it, and open:

   https://your-domain.example/p/your-page-slug

Advanced option (ideal hardening)
---------------------------------

For VPS or when you control the vhost directly, you may point document root at
apps/api/public instead and use deploy/nginx/luma.conf or deploy/apache samples.
This is optional — the default archive-root entry works on most shared panels.

Pure nginx without Apache (.htaccess)
-------------------------------------

If your host does not process .htaccess, paste deploy/nginx/luma-root.conf.example
into your panel (adjust root path and PHP socket).

Optional security (recommended before exposing setup to the internet)
---------------------------------------------------------------------

Set a setup token in apps/api/.env:

   LUMA_SETUP_TOKEN=your-long-random-token

Build Studio with the same value as VITE_LUMA_SETUP_TOKEN so the wizard sends
header X-Luma-Setup-Token on setup API requests.

Passwords
---------

Use a strong owner password (minimum 12 characters). Avoid password, admin,
change-me, and other common defaults.

Optional cron (webhooks / queue)
--------------------------------

   * * * * * php ~/path/to/apps/api/artisan schedule:run

Legacy admin URL
----------------

/studio/ redirects to /admin/ — use /admin/ as the canonical admin path.

Developer install (secondary)
-----------------------------

CLI install (php artisan luma:install) exists for developers and automation.
See docs/installation.md.

Troubleshooting
---------------

- 403 on /admin/setup: enable AllowOverride for .htaccess, or use nginx sample
- 500 before setup: check storage/ and bootstrap/cache/ permissions
- Database cache error: ensure CACHE_STORE=file in .env until setup completes
- open_basedir errors: contact host or use VPS with full path access

Web server samples
------------------

See deploy/nginx/luma-root.conf.example (archive root) or deploy/nginx/luma.conf
(document root = apps/api/public).
